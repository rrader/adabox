# Jukebox / AdaBox

Саморобний RFID-плеєр для доньки (Ада) в дусі Toniebox / TonUINO / ESPuino: без WiFi, застосунку й хмари — тільки картки, кнопки й енкодер.

## Залізо та розпіновка

ESP32 devkit (Keyestudio ESP32-WROOM-32D), DY-SV5W (TF до 32 ГБ, динамік 5 Вт 4 Ом), WS2812 16 LED кільце, RC522, енкодер KY-040/EC11, 3 кнопки, живлення — модуль 2×18650 Type-C 5V.

| Компонент | GPIO |
|---|---|
| DY-SV5W RXD / TXD / BUSY | 17 (TX2) / 16 (RX2) / 15 (BUSY LOW = грає) |
| WS2812 DATA | 4 |
| Кнопка Play/Stop / Next / Prev | 12 / 14 / 13 (INPUT_PULLUP → GND) *(Next=14, Prev=13, README узгоджено з прошивкою)* |
| Енкодер CLK / DT | 18 / 19 (SW не використовується) |
| RC522 SCK / MISO / MOSI / SS / RST | 25 / 26 / 27 / 5 / 22 |

DIP-перемикачі DY-SV5W: UART-режим CON3=1, CON2=0, CON1=0. UART 9600 8N1.
Залежності Arduino IDE: плата **ESP32 Dev Module**, бібліотеки **FastLED ≥ 3.6**, **MFRC522**; `Preferences` — вбудована в ESP32 core. Прошивка: `scripts/flash.sh build|upload [port]` (arduino-cli з Arduino IDE, збирає на місці; головний файл скетча називається `jukebox.ino`, щоб збігатися з назвою папки `jukebox` (вимога Arduino); FQBN `esp32:esp32:esp32`, ESP32 core 3.3.8, FastLED/MFRC522 вже встановлені). Плата Романа: ESP32-D0WD-V3 rev 3.1, 4 МБ флеш, USB-міст CP2102 (`/dev/cu.usbserial-0001`), MAC 30:76:f5:ee:bc:04; `esptool` є в brew. Збірка: ~411 КБ (31%) флеш, 24 КБ RAM. Не змінювати Partition Scheme / не вмикати Erase All Flash — інакше стирається NVS.

## Керування

- **Play/Stop** (відпускання): грає → стоп (червоний флеш); стоїть → грає поточний трек поточного режиму (зелений флеш).
- **Next / Prev**: наступний/попередній трек у поточному режимі (циклічно), одразу грає, comet-sweep (cyan CW / yellow CCW).
- **Prev утримана + енкодер**: яскравість LED (рівень 0–10, 0 = підсвітка вимкнена, за замовчуванням і максимум 10 = базові 90 MUSIC / 35 OTHER; множник `рівень/10`), дію Prev на відпускання пригнічено; зберігається (ключ `led`).
- **Енкодер**: гучність; з утриманою Play — перемотка ±5 с на тік (`SEEK_SECONDS`).
- **Утримання Next 5 с, коли не грає**: перемикання режиму MUSIC (orange flash) ↔ OTHER (purple flash).
- **Програмування картки**: утримати Next+Prev одночасно → режим програмування (бігуча анімація, мінімум 5 с), прикласти картку → записується повний шлях поточного треку (`/MUSIC/00003.mp3`) → success-анімація.
- **Скидання пам'яті**: усі 3 кнопки (Play+Next+Prev) утримувати 15 с (`FACTORY_RESET_MS`) → `factoryReset()` стирає namespace `jukebox` у NVS (режим, треки, гучність, яскравість, позиції казок), LED 3 рази блимають червоним на повну яскравість (навіть при рівні 0), плата перезавантажується зі значеннями за замовчуванням. Перед цим на 5 с спрацьовує вхід у режим програмування RFID (побічний ефект комбінації).
- **RFID**: картка зберігає **повний шлях** (32 байти; MIFARE Classic і NTAG), не номер треку, тому карти не ламаються при перестановці — лише при перейменуванні файлів. Повторне прикладання картки того ж треку, що вже грає, ігнорується.
- **Режими**: `MUSIC` — автоперехід на наступний трек після завершення (BUSY-детекція, 200 мс), яскравість LED 90; `OTHER` (казки) — без автопереходу, яскравість 35 під час відтворення.

## Константи та стан (jukebox.ino)

- Гучність: `VOLUME_MIN 2`, `VOLUME_MAX 14` (шкала модуля 0–30; було 21, зменшено в 1.5 раза), `VOLUME_DEFAULT 8`. Гучність зберігається (ключ `vol`) через 2 с після останнього тіку енкодера.
- **Збережений стан (NVS, namespace `jukebox`)**: ключі `music`, `rfid` (останній трек кожного режиму), `vol`, `led` (рівень яскравості) і `mode` (0=MUSIC, 1=OTHER). `loadState()` після підрахунку треків у `setup()` (обмежує номер кількістю файлів), `saveStateIfChanged()` в кінці `loop()` пише у флеш лише при зміні. Після вмикання плеєр стоїть; Play грає збережений трек.
- Кількість треків визначається на старті: `playerQueryFolderCount()` грає трек 1 папки, стопить і шле `0x12` (парсить відповідь `AA 12 02 HI LO SM`).
- Іконка вмикання/перемикання змінних треку: `musicTrack`, `rfidTrack` (1-based).

## Запам'ятовування позиції в OTHER

Модуль не повертає час відтворення, тому прошивка рахує його сама (`posBaseMs`/`posStartMs`, корекція на seek) і пише в NVS ключ `p<N>` (секунди) для кожного OTHER-треку: кожні 15 с під час відтворення, при Stop, при Next/Prev/зміні на MUSIC. Кінець треку → позиція 0. Відновлення — Play, Next, Prev (крім перезапуску) або карткою `/OTHER/xxxxx.mp3`: `trackOther(N, true)` через 300 мс після старту шле `playerSeek(saved)`; позиція < 5 с ігнорується. Next/Prev теж продовжують казку зі збереженої позиції; Prev на казці, що грає понад `PREV_RESTART_S` (10 с), перезапускає її з початку (як у звичайних плеєрах), інакше — попередня казка з її збереженої позиції (лише OTHER). Точність ~секунди (обрив живлення втрачає до 15 с).

## Автовимкнення (deep sleep)

`IDLE_SLEEP_MS` = 10 хв без відтворення й без активності кнопок/енкодера/карток → `goToSleep()`: зберігає стан, стопить плеєр, гасить LED, deep sleep. Пробудження — кнопка Play (GPIO 12, `ext0`, active LOW; ext1 ANY_LOW на ESP32 не працює, тому будить лише Play); плата перезавантажується й відновлює стан із NVS. Модуль DY-SV5W і RC522 лишаються під живленням (повне відключення — лише фізичним вимикачем).

## Протокол DY-SV5W (player.ino)

Кадр: `AA type len data… crc` (crc = сума всіх байтів до crc, mod 256). **Seek (`0x23`/`0x22`) у datasheet SV5W відсутній, але на залізі ПРАЦЮЄ (підтверджено Романом 2026-10-31: Play+енкодер перемотує).** Задокументовані команди: `07` вибір треку за номером, `0C` кількість усіх файлів, `0D` поточний трек, `11` перший трек папки, `12` кількість у папці (запиту поточного часу немає), `0E/0F` папка prev/next, `14/15` vol+/−, `18/19` режим циклу.
Команди: `02` play, `03` pause, `04` stop, `05/06` prev/next, `13` volume (0–30), `12` кількість файлів у поточній папці, `23/22` перемотка вперед/назад на N секунд, `08` грати за шляхом.
**Кодування шляху для `08`**: перед шляхом байт пристрою `01` (SD); кожен `/` після першого → `*/`, `.` → `*`, літери у верхній регістр: `/MUSIC/00001.mp3` → `/MUSIC*/00001*MP3`. Інакше модуль мовчки ігнорує. Референс: github.com/SnijderC/dyplayer. Повний datasheet: `DY-SV5W-3.md`.

## SD-карта

FAT32, один розділ MBR, дві папки: `MUSIC/` і `OTHER/` з файлами `00001.mp3`… (**5 цифр**, без пропусків). Плюс `tracklist.txt` у корені — рядки `MUSIC/00001.mp3 = Оригінальна назва.mp3` (веде sd-manager; прошивці не потрібен). На macOS стежити за `._*` junk-файлами (sd-manager їх знаходить і видаляє). Монтується як `/Volumes/SDCARD`.

## sd-manager.html (заливка музики)

Статична веб-сторінка (Chrome/Edge — потрібен File System Access API `showDirectoryPicker`), відкривати локально: `open projects/jukebox/sd-manager.html`. Залежність: lamejs з cdnjs (потрібен інтернет). Можливості:
1. «Open SD card» → читає `MUSIC/` та `OTHER/`, `tracklist.txt`, показує сирітські записи й junk.
2. Перетягнути MP3 у чергу, обрати папку (MUSIC/OTHER) для кожного, обрізати тишу/інтро (✂ Trim, Preview), кодує через lamejs у моно/стерео MP3.
3. Запис на карту з автонумерацією наступним вільним номером (`safeNextNum`), оновлення `tracklist.txt`.
4. Редагування вже записаного (trim на карті), перейменування/перенумерація з компактизацією (щоб не було дір), видалення вибраних, очищення junk.
Порядок роботи: `download_track.py` → файли в `mp3/` → перетягнути в sd-manager → вибрати MUSIC/OTHER → записати → вставити карту в плеєр.

## Типові задачі

- **Змінити поведінку/гучність/анімації** → правити `.ino`, перевірити `Serial` лог (115200), Роман збирає й заливає через Arduino IDE. Не вигадувати, що прошивку залито.
- **Нова картка** → вибрати трек Next/Prev у потрібному режимі, Next+Prev, прикласти картку.
- **Додати треки/казки** → розділ нижче + sd-manager. Казки — в `OTHER`.
- Після змін комітити в репо adabox (checklist: remote `github-personal`, email `antigluk@gmail.com`).

## Пошук і завантаження треків

Нижче — деталі скрипту завантаження (колишній скіл `jukebox-tracks`).

## Розташування файлів та структура

- **Скрипт завантаження:** `projects/jukebox/scripts/download_track.py`
- **Папка для вхідних MP3:** `projects/jukebox/mp3/` (вихідні аудіофайли зі зрозумілими назвами для перегляду та імпорту)
- **Веб-інтерфейс SD карти:** `projects/jukebox/sd-manager.html` (веб-утиліта для нарізки, нумерації та запису на FAT32 SD-карту)
- **SD-карта Jukebox (FAT32):**
  - `MUSIC/00001.mp3`, `MUSIC/00002.mp3`, ... (основний режим відтворення з автопереходом)
  - `OTHER/00001.mp3`, `OTHER/00002.mp3`, ... (казки / окремі треки без автопереходу)

## Вимоги до оточення

Для завантаження та конвертації використовуються:
1. `uvx yt-dlp` із прапорцями:
   - `--remote-components ejs:github` (вирішення YouTube JS challenges)
   - `--js-runtimes node:/opt/homebrew/bin/node` (підтримка Node.js для обробки YouTube n-sig/challenge)
   - `-x --audio-format mp3 --audio-quality 0`
2. `ffmpeg` (`/opt/homebrew/bin/ffmpeg`) для вилучення звукової доріжки у чистий MP3 (CBR/VBR 44.1/48 kHz).

## Як завантажувати треки

### 1. Через вбудований скрипт

```bash
# Один трек за запитом
python3 projects/jukebox/scripts/download_track.py "The Duck Song"

# Декілька треків одночасно
python3 projects/jukebox/scripts/download_track.py "Crazy Frog Axel F" "Cartoons Witch Doctor"

# З явною назвою файлу та URL (рекомендовано для точності):
python3 projects/jukebox/scripts/download_track.py "П'ятеро жабенят=https://www.youtube.com/watch?v=9k86-F3KVi0"
```

Скрипт автоматично:
- Шукає найкраще аудіо або використовує наданий URL.
- Очищає назву від емодзі, зайвих суфіксів на кшталт `[Official Video]`, `| З любов'ю до дітей`.
- Конвертує аудіо в якісний MP3 через `ffmpeg`.
- Зберігає у `projects/jukebox/mp3/<Назва>.mp3`.

### 2. Прямий виклик yt-dlp (якщо потрібні специфічні параметри)

```bash
uvx yt-dlp \
  --remote-components ejs:github \
  --js-runtimes node:/opt/homebrew/bin/node \
  -x --audio-format mp3 --audio-quality 0 \
  -o "projects/jukebox/mp3/%(title)s.%(ext)s" \
  "<URL або ytsearch1:...>"
```

## Правила підбору треків для Jukebox

1. **Дитячі версії та чистий звук:**
   - Для дитячих пісень надавати перевагу оригінальним україномовним релізам (наприклад, Назар Савко / «З любов'ю до дітей», «Першосвіт») або офіційним audio-track версіям без тривалих діалогів чи відео-інтро на початку.
2. **Очищення назв:**
   - Зберігати зрозумілі, лаконічні назви файлів без сміття, наприклад `Булька.mp3`, `Муха Роботуха.mp3`, `Axel F - Crazy Frog.mp3`.
3. **Підготовка до картки через sd-manager.html:**
   - Після завантаження нагадати користувачеві, що файли готові в `projects/jukebox/mp3/` і їх можна перетягнути у `sd-manager.html` для обрізки тиші/інтро та автоматичної генерації структури `00001.mp3` для SD-карти.
